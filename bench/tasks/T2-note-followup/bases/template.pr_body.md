- **API**: `PUT /api/daily-records/{date}/note`
  - 本文 `{ "note": "..." }`。前後の空白を除いて 200 文字まで。空（空白だけ）を送るとメモを消す
  - 201 文字以上・文字列でない（無い・`null` も含む）ときは 400（`fieldErrors[].field` は `"note"`）。実在しない日付は 400
  - その日の記録が無ければ 404（「その日の記録が見つかりません」）
  - 200 で、メモを付けた後のその日の記録（`DailyRecord`）を返す
- **DB**: マイグレーション 4 で `daily_records` に `note TEXT`（NULL 可）を追加。今までの記録は NULL（メモなし）のまま読める

### 自分で決めたこと（質問できなかったため）
1. **メモの保存は「メモを保存」ボタンで行う。** 勤務区分は選んだ時点で保存する（U4）が、メモは文章なので、打ち終えてから保存する。前後の空白だけが違うときは「変わっていない」とみなし、ボタンを押せない
2. **未入力の日にはメモを付けられない。** API の仕様（記録が無ければ 404）に合わせ、パネルには「メモは、先に勤務区分を選んでから付けられます」と出す。メモだけの記録は作らない
3. **一括設定の当てはめ中は、パネルでメモを見せるだけにする。** 当てはめ中は「選んだ内容は『登録』でまとめて保存する」なので、すぐ保存するメモの欄は出さない（追加の移動と同じ扱い）
4. **未入力に戻す（記録を消す）と、メモも消える。** 追加の移動と同じ。確認の文は変えていない（追加の移動があるときだけ確認を出す今の動きのまま）
5. **移動の無い日（在宅・休日で追加の移動が無い日）は、メモがあっても CSV の行を作らない。** F7 の「1行 = 1つの移動」を守るため。メモはその日に移動の行があるときだけ CSV に出る
6. **「文字列でない」には、`note` が無い・`null` も含める。** 消すときは空の文字列を送る
7. **文字数は JavaScript の `length`（UTF-16 の単位）で数える。** backend と画面で同じ数え方。絵文字など一部の文字は2文字に数えられる
8. **カレンダーのマスにはメモの印を出していない。** Task の範囲（パネルと表）に絞った
