## 概要
ルートの一覧に同じ名前（例:「自宅↔本社」）が並び、出勤を選ぶときに区別できなくなる問題を防ぐため、同じ名前のルートを登録できないようにする。

## 変更
- `POST /api/routes`: 同じユーザーにすでに同名のルートがあれば、登録せずに 409 を返す。本文は既存と同じ形（`error: "入力に誤りがあります"`、`fieldErrors: [{ field: "name", message: "同じ名前のルートがあります" }]`）
- `RouteRepository` に `existsByName(userId, name)` を追加（SQLite 実装も）
- 画面: 変更なし。API クライアントは 400 と同じく本文の `fieldErrors` をそのまま返し、フォームが `name` の欄の下に出す（今の入力の誤りと同じ出し方）。このことをテストで固定した
- `docs/api/openapi.yaml` に 409 を追記
- テスト: ルーターの 409 / 別名は 201 / リポジトリの `existsByName` / 画面側の 409 の扱い

## 自分で決めたこと
- **名前の比べ方は、前後の空白を除いた後の完全一致**。入力の検証（`parseRouteInput`）がすでに前後の空白を除くので、それに任せた。大文字小文字・全角半角・「↔」と「<->」などの違いは同じとは見なさない
- **同じ名前かどうかはユーザーごとに判定**（他のユーザーのルートとは重ならなくてよい）
- **編集（`PUT /api/routes/:id`）は今回の対象外**。依頼が登録のみだったため。このため、編集で既存と同じ名前に変えることはまだできてしまう。必要なら、自分自身を除いて同じ判定を足す別の変更にするのがよい
- **DB の UNIQUE 制約は足していない**。すでに同名のルートがあるデータでマイグレーションが失敗するおそれがあるため。判定は API の層で行っている（同期の SQLite で、1つのリクエスト内で確認から登録まで割り込みなく進むので、重複は起きない）。すでにある同名ルートはそのまま残る
