## 概要
転勤で使わなくなったルートが増え、ルートの一覧と出勤の選択肢がごちゃごちゃしてきたので、ルートを「アーカイブ」して片付けられるようにする。

削除は今もできるが、元に戻せないので「また使うかもしれないルート」は消しにくい。アーカイブは消さずにしまうだけなので、いつでも元に戻せる（選んだ理由は ADR-0004）。

## 変更内容
- **ルートの画面**: 各ルートに「アーカイブ」ボタン。アーカイブしたルートは「アーカイブ済みのルート（N件）」の折りたたみ（最初は閉じている）に移り、そこで「元に戻す」「編集」「削除」ができる
- **選択肢**: アーカイブ済みのルートは、出勤（日の編集・一括設定）と追加の移動の選択肢に出ない（`CalendarPage` で読み込み時に除く）
- **API**: `PATCH /api/routes/:id`（本文 `{ "archived": true | false }`）を追加。`GET /api/routes` はアーカイブ済みも含めて返し、`Route.archived` で見分ける。`PUT`（編集）はアーカイブの状態を変えない。`docs/api/openapi.yaml` も更新（`openapi.test.ts` の API の数を 15 → 16）
- **API の受け口**: アーカイブ済みのルートを出勤に選ぶと 400（`workStyle.routeId`「選んだルートが見つかりません」。一括設定の `days[i].workStyle.routeId` も同じ）。別のタブの古い画面からでも、アーカイブ済みのルートで記録ができないようにするため
- **DB**: マイグレーション 4 で `routes.archived INTEGER NOT NULL DEFAULT 0` を追加（今までのルートは「使っている」のまま読める）
- **型**: `shared` の `Route` に `archived: boolean`。`RouteInput` には入れない
- **過去の記録は変わらない**: 記録は作った時点のルートの値を持っているので（U7）、表示・金額・CSV に影響しない
- **文書**: ADR-0004、`docs/requirements.md`（F1・Route の項目・U11）、`docs/troubleshooting.md`（メッセージの原因と、アーカイブした後の見え方）、`docs/PROGRESS.md`
- **テスト**: リポジトリ（アーカイブ・元に戻す・編集してもアーカイブのまま・他のユーザーは不可）、API（200・400・404）、日次記録の API（アーカイブ済みは出勤に選べず、戻せば選べる）、画面の `partitionRoutes`・`setRouteArchived`

## 自分で決めたこと
依頼は短く、やり方が決まっていなかったので、次のように決めた。

- **「片付ける」= 削除ではなくアーカイブ**にした。削除はすでにあるので、足りないのは「消さずにしまう」手段と考えた。削除は残してある
- アーカイブした日時は持たず、真偽値だけにした（今は使い道が無いため。要るなら後でマイグレーションを足す）
- アーカイブ済みの切符は、一覧から消さずに折りたたみの中に置く（戻す操作をその場でできるようにするため）
- エラーの文は新しく作らず、既存の「選んだルートが見つかりません」を使った。アーカイブ済みだと分かる文のほうが親切だが、メッセージを増やすと画面・テスト・手順書の直しが増えるので、`docs/troubleshooting.md` に原因として書くにとどめた。気になるなら別の PR で文を分ける
- 「最近使っていないルートを自動で隠す」案は、季節に1回だけ使うルートまで隠れるので見送った（比較は ADR-0004）

## 動作確認の方法
```bash
npm install
npm run typecheck && npm run lint && npm run test   # 260 件が通る
npm run dev   # http://localhost:5173
```

1. 「ルート」でルートを2つ登録する

5. 「ルート」の折りたたみを開いて「元に戻す」→ 選択肢に戻る
6. （API）`curl -X PATCH localhost:3000/api/routes/<id> -H 'Content-Type: application/json' -d '{"archived":true}'` → 200。`{"archived":"x"}` → 400
