## 背景
転勤で使わなくなったルートが、ルートの一覧と出勤の選択肢に残り続けてごちゃごちゃする。

## 変更内容
ルートに「使わない」（アーカイブ）の状態を足した。**削除とは別の、元に戻せる片付け**。

- ルート管理画面の各ルートに「使わない」ボタンを追加。押すとそのルートは
  - 「登録済みのルート」の一覧から外れ、下の折りたたみ「使わないルート（N件）」に移る
  - カレンダーの日の選択肢・一括設定の選択肢・追加の移動のルート選択に出なくなる
- 「使わないルート」の中では「使用中に戻す」で元に戻せる（編集・削除もそのまま可能）
- API: `PATCH /api/routes/{id}`（`{ "archived": boolean }`）を追加。`GET /api/routes` は既定で使用中のルートだけを返し、`?includeArchived=true` で全件を返す（管理画面が使用）
- DB: マイグレーション v4 で `routes.archived`（既定 0）を追加。既存のルートは全て使用中のまま
- `shared` の `Route` に任意項目 `archived` を追加（`RouteInput` には含めない）
- `docs/requirements.md`（F1・データ項目・決定事項 U11）と `docs/api/openapi.yaml` を更新

## 自分で決めたこと
1. **削除は残し、別に「使わない」を足した。** 削除は既に画面・API にあり、記録の金額と区間も変わらない。ただし元に戻せない（転勤で戻る可能性や、名前・運賃・URL の入れ直しを考えると、戻せる手段が欲しい）ため、元に戻せる方を足した。不要なら「削除」を使えばよい。
2. **既定の一覧 API を使用中だけにした。** 選択肢を使う側（カレンダー等）のコードを変えずに済むため。管理画面だけ `includeArchived=true` を付ける。
3. **「使わない」にしたルートを使っている既存の記録は、そのまま残し、同じ日を保存し直すこともできる。** 記録の作成時のルートの確認は引き続き `get`（使わないルートも引ける）で行うので、API としては使わないルートの新規指定も通る。画面の選択肢から外すだけで、API では禁止していない（個人用アプリで、過去の記録の保存し直しを壊さないことを優先）。
4. **使わないルートを編集しても使わないままにした。**
5. 当初の要望にある「一覧」は、使わないルートを完全には隠さず、折りたたみで残した（戻すために必要なため）。完全に消したいときは削除する。
