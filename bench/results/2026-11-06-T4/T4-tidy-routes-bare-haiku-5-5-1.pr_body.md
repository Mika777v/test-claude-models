## 概要

転勤などで使わなくなったルートを「しまう」ことで片付けられるようにした。
しまったルートは、出勤・追加の移動・一括設定の選択肢に出なくなる。ルートの管理画面では「しまったルート」として分けて残すので、戻すこともできる。

## 変更内容

- **shared**: `Route` に `archived: boolean` を足した。`RouteInput` からは外した（しまう・戻すは値の編集とは別の操作にするため）。
- **backend**
  - マイグレーション v4: `routes.archived`（既定 0）を追加。今までのルートは使用中のまま。
  - `PUT /api/routes/:id/archived`（本文 `{ "archived": true | false }`）を追加。400（true / false 以外）・404 を返す。
  - `RouteRepository.setArchived` を追加。編集（`update`）ではしまう状態を変えない。
  - `docs/api/openapi.yaml` に追記。`openapi.test.ts` の API 数を 15 → 16 に更新。
- **frontend**
  - ルートの管理画面: 「使っているルート」と「しまったルート（n件）」に分けて表示。各ルートに「しまう / 戻す」を追加。
  - 出勤の選択肢（日の編集パネル・一括設定）と、追加の移動のルート選択から、しまったルートを外す（`selectableRoutes`）。
  - 追加の移動を直すとき、元のルートがしまってあっても選択欄が空に見えないように、そのルートだけは残す。
  - 日の編集パネルでは、今の記録がしまったルートなら、従来どおり記録のコピーの名前で「出勤（…）」と出る。
- **docs/requirements.md**: F1 に「しまう」を追記、データ項目（`archived`）を追記、決定の記録に U11 を追加。

## 決めたこと（レビューで見てほしい点）

1. **削除ではなく「しまう」にした。** 削除は今までどおり使える。しまえば、いつでも戻せて、過去のルート名も一覧で確かめられる。
2. **サーバーは、しまったルートを出勤に選ぶ要求も受け付ける。** 選択肢に出さないのは画面だけ。
   理由: 既存の記録を保存し直すときに、しまったルートを指していると 400 になって困るため。新規に選ばせない強制は、必要になったら別の変更にする。
3. **しまう操作では `updated_at` を変えない。** 「値の更新」ではないため。
4. **しまったルートの扱いは、記録のコピーに従う。** 記録の金額と区間はしまっても変わらない（F1・U7 と同じ考え方）。
