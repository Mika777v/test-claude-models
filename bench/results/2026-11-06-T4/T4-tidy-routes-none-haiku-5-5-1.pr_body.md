## 概要

転勤などで使わなくなったルートを、削除せずに「しまう」ことができるようにしました。
しまったルートは、出勤の選択肢（日の勤務区分・一括設定・追加の移動）に出さず、ルートの画面では下の「しまったルート」にまとめます。過去の記録は変わらず、「戻す」で元に戻せます。

## 変更内容

- **shared**: `Route` に `archived: boolean` を足した。`RouteInput` からは外した（しまう・戻すは別の API で行うため）。
- **backend**
  - DB マイグレーション version 4 で `routes.archived` 列を足した（既定値 0 = 使っている。既存のルートはそのまま読める）。
  - `PUT /api/routes/:id/archived`（本文 `{ "archived": boolean }`）を追加。真偽値でなければ 400、無いルートは 404。
  - 編集（`PUT /api/routes/:id`）では `archived` を変えない。
  - `docs/api/openapi.yaml` に新しい API と `Route.archived` を書いた（`openapi.test.ts` の件数も 16 に更新）。
- **frontend**
  - ルートの一覧で「しまう / 戻す」ボタンを追加。使っているルートと、折りたたみの「しまったルート（N件）」に分けて表示。
  - 日の勤務区分・一括設定・追加の移動が読むルートは、しまったものを外す（`pickableRoutes`）。
- **docs**: `docs/requirements.md` の F1 に説明を足し、決定の記録に U11 を追加した。

## 決めたこと（レビューで見てほしい点）

1. **「削除」とは別の「しまう」にした。** 既存の削除は残し、しまうは選択肢から外すだけで戻せる状態にした。転勤で「いつか戻るかもしれない」ルートを消さずに片付けられるようにするため。
2. **API は、しまったルートを記録の `routeId` に使うこと自体は止めない。** 画面に出さないだけにした。API で止めると、しまったルートを使う既存の記録を編集するときに、不都合が起きやすいため。
3. **既存の記録の表示は変えない。** しまったルートを使う日は、選択中の選択肢として「出勤（ルート名）」が出る（削除済みルートの既存の扱いと同じ）。記録のコピー（`RouteSnapshot`）を使うので、金額と区間は変わらない。
4. **追加の移動の既存の出どころ（`sourceRouteId`）は変えない。** 追加の移動の編集フォームでは、しまったルートを元にした移動の「登録済みのルートから選ぶ」欄が「手で入力する」と出る（値は保存されたまま）。これは既存の「削除済みルートを元にした移動」と同じ挙動で、今回は直していない。
