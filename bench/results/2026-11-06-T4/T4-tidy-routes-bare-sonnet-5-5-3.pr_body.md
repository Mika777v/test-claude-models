## 概要
転勤などで使わなくなったルートを、消さずに片付けられるようにしました。「使わない」にしたルートは、ルート一覧（初期表示）と、出勤・追加の移動の選択肢から外れます。あとから「使用中に戻す」こともできます。

## 変更内容
- **DB**: マイグレーション 4 で `routes.archived`（0/1、既定 0）を追加。既存のルートはすべて使用中のままです。
- **API**: `PATCH /api/routes/:id/archived`（`{ "archived": boolean }`）を追加。`Route` に任意の `archived` を追加（使用中なら項目なし）。`docs/api/openapi.yaml` と `docs/requirements.md`（F1）も更新しました。
- **ルート画面**: 各ルートに「使わない」/「使用中に戻す」ボタンを追加。使わないルートは初期表示では隠し、「使わないルートも表示する（N件）」のチェックで見られます。
- **カレンダー画面**: 出勤のボタン、一括設定、追加の移動の選択肢から、使わないルートを外しました。
- テストを追加しました（リポジトリ、API、フロントの API クライアント）。`npm run typecheck`、`npm run lint`、`npm run test` はすべて通っています。

## 判断したこと
- **削除ではなくアーカイブを足した**。削除はすでにありますが、元に戻せません。「使わなくなった」ものを片付けたいという依頼なので、戻せる方法を足しました。削除ボタンはそのまま残しています。
- **過去の記録は変わらない**。記録にはルートのコピーがあるためです。使わないルートを出勤で選んでいた日は、これまでの「ルートが一覧に無い」ときと同じく、記録のコピーから選択肢を補います。
- **編集しても「使わない」の印は変わらない**。印は `RouteInput` に入れず、専用の API で切り替えます。
- **`GET /api/routes` は使わないルートも返す**。隠すかどうかは画面側で決めます。ルート画面では切り替えて表示でき、カレンダーでは隠します。
- **サーバー側では、使わないルートを指定した記録の保存を拒否しない**。使わないルートの日を再保存したり、古い画面から保存したりしても失敗させないためです。選択肢から外すのは画面側だけです。
