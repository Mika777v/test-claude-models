## 概要

転勤などで使わなくなったルートを片付けられるようにした。ルートを「使わなくする（アーカイブ）」と、ルートの一覧と出勤の選択肢から外れ、新しく選べなくなる。消さないので「使うに戻す」で元に戻せる。過去の記録は変わらない（記録は作った時点のルートの値をコピーして持つため）。既存の「削除」はそのまま残す。

決めた理由と選択肢は `docs/adr/0004-archive-routes.md`。

## 自分で決めたこと

- 「片付けたい」の読み方: 削除は既にあるので、足りないのは「戻せる形で外す」だと判断した。削除は消さずに残した
- アーカイブ・使うに戻すに確認は出さない（取り消せるため）。削除の確認はそのまま
- 最初にアーカイブした時刻を `archived_at` に残す（もう一度アーカイブしても変えない）。画面には出していない
- `?archived=` の値は `true` / `false` だけを受け付ける
- 画面の文: 使っているルートが無いときの文を「使っているルートがありません」に変えた（今までは「まだルートがありません」。アーカイブだけが残っている状態で誤解を招かないように）。文の変更なので、困ったときの手順書は該当なし

## 動作確認の方法

```
npm run dev
```

ブラウザで http://localhost:5173 を開く。

1. ルートを2つ登録する
2. 片方の「使わなくする」を押す → 一覧から消え、下の「使わなくなったルート」に出る。メッセージに「過去の記録は変わりません」と出る
3. 日をクリックする → 出勤の選択肢に、使っているルートだけが出る
4. 「使うに戻す」を押す → 一覧に戻る
5. 出勤にした日の記録（アーカイブ前に記録したもの）は、アーカイブ後も「出勤（ルート名）」と出る

API で確かめる（backend は 3000 番）:

```
curl -X PUT localhost:3000/api/routes/<id>/archived -H 'Content-Type: application/json' -d '{"archived":true}'
curl 'localhost:3000/api/routes?archived=true'
```
