## 概要

- **DB・型**: マイグレーション v4 `ALTER TABLE routes ADD COLUMN archived_at TEXT`（既存の行は NULL＝使う）。`Route` に `archived: boolean`（`RouteInput`・`RouteSnapshot` には入れない）
- **API**

```bash
npm install

npm run dev                                          # 手元の DB は起動で v4 になる
```
画面（http://localhost:5173）:
1. 「ルート」でルートを2つ以上登録 → 片方の「使わない」を押す。「『◯◯』を使わないルートにしました」が出て、一覧の下の「使わないルート（1件）」に移る。リロードしても保たれる
2. 「カレンダー」で日を開く → 出勤の選択肢・「一括設定」のルート選択・追加の移動の「ルートから選ぶ」に、使わないルートが出ない
3. そのルートを使った過去の日を開く → その記録のルートが選択肢に残って選ばれている。金額・合計・CSV は変わらない
4. 「使わないルート」で「戻す」→ 元の一覧に戻り、選択肢にも出る。使わないルートの「編集」「削除」もできる

API（backend 起動中）: 使わないルートの `routeId` で `PUT /api/daily-records/2026-11-02` → 400。`POST /api/routes/<id>/archive` を2回 → どちらも 200。存在しない ID → 404。
