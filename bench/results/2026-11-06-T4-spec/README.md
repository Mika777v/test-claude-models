# T4 を「Opus が要件を詰めて、Sonnet が実装する」で動かした結果 — 2026-11-06

- 目的: 担当ごとにモデルを変える運用のうち、「最初の要件を詰めるところを Opus にする」が効くかを見る
- Task: [`tasks/T4-tidy-routes/task.md`](../../tasks/T4-tidy-routes/task.md)「使わなくなったルートを片付けたい」（わざと曖昧）
- 土台: routepense `d4d15fd`。条件は template（ルールあり）
- 流れ（`run.sh` の `BENCH_SPEC_MODEL`）:
  1. Opus が同じ作業場所でリポジトリを調べ、`SPEC.md` を書く（コードは変えない。3回とも、触ったのは `SPEC.md` だけだった）
  2. 作業場所を元に戻し、Sonnet に「Task ＋ 詰めた要件」を渡して実装させる
- ベンチではオーナーに聞けないので、Opus のおすすめの答えを「オーナーが確かめた」扱いで渡している。比べる相手は、要件の段階が無い「Sonnet・ルールあり」の3回（[`../2026-11-06-T4/`](../2026-11-06-T4/README.md)）
- 各3回。要件の段階も毎回やり直した。生の結果: `*.spec.md`（Opus が書いた要件）・`*.score`・`*.pr_body.md`・`*.diff`・`results.tsv`（実装の段階）・`spec-usage.tsv`（要件の段階）

## わかったこと

1. **読み方の揺れは消えた。** Sonnet だけでは「作らずに聞く」と「消さずに隠すを作る」に割れたが、要件を詰めた後は3回とも同じものを作った。Opus の要件も、大筋（削除は残し、「使わない」の印を足す。出勤・一括設定・追加の移動の選択肢のすべてから外す。一覧の下に畳んで出し、戻せる）は3回ともそろった
2. **Sonnet は、渡された要件に忠実に作った。** 要件の細かいところは Opus の回ごとに違った（API の形、印を日時で持つか真偽値か、一覧の API が全件を返すか）。中でも1回だけ「しまったルートで新しく出勤を記録したら 400 にする」を勧め、その回の実装だけが 400 にした（ほかの2回は、要件どおり受け付けた）。揺れは、実装の段階から要件の段階に移った
3. **移った揺れは、オーナーに見える形になっている。** Opus の要件には、毎回 8〜12 個の「オーナーに確かめること」があり、それぞれに選択肢・おすすめ・理由が付いていた（例: 「しまったルートを記録に新しく使えるか」「削除は残すか」「一度に何件もしまうか」）。実際の運用では、オーナーがここで答えを決めるので、回ごとの違いはオーナーの答えでそろう。ベンチではオーナーが答えないので、この効果は測れていない
4. **費用は約3.2倍。** 要件の段階（Opus）だけで、Sonnet だけの1回分より高い。実装の段階も、要件が細かい分だけ重くなった（120.7万 → 180.3万トークン）

つまり、要件を Opus で詰めると、**AI が勝手に決めていた部分が、オーナーへの質問の一覧に変わる**。そこにオーナーが答える運用なら、曖昧な依頼でも結果がそろう。費用は上がるので、曖昧な依頼や Epic の始めに絞るのがよい。

## 要件を Sonnet で詰めた場合（追加・各3回）

| | Sonnet だけ | Opus で要件 → Sonnet | Sonnet で要件 → Sonnet |
|---|---|---|---|
| 「片付ける」の読み方 | 作らずに聞いた 1・消さずに隠す 2 | 消さずに隠す 3 | 消さずに隠す 3 |
| 申告・ADR | 2/2 | 3/3 | 3/3 |
| 要件の段階の質問の数 | ― | 8・10・12 | 6・7・7 |
| 「しまったルートで新しく出勤を記録したら 400」を勧めた | ― | 1/3 | 2/3 |
| 受け入れテスト | すべて 3/3 | すべて 3/3 | すべて 3/3 |
| 費用（平均） | $0.52 | $1.65（要件 $0.87） | $1.32（要件 $0.33） |

- 要件を Sonnet で詰めても、読み方の揺れは同じく消えた。「片付ける」の意味は3回とも1つ目の質問にし、1回は「今ある削除で足りるのでは」を選択肢の A に置いた
- 質問は Opus より少ない（6〜7個）。見せ方の細かい質問（呼び名・並び順・検索）が減り、業務の決まり（隠したルートを記録に使えるか・既存の記録の扱い）は残った
- 細かいところの揺れ（400 にするか）は、Opus と同じく残った
- 要件の段階の費用は Opus の約4割。合計では Opus の約8割（実装の段階が少し重くなった）
