## わかったこと

1. **どちらの Task でも、要件の段階の Y はいちばん低い。** Q はいちばん高い（T5 の Opus は 1.00）が、費用が 4〜6倍になる。T5 で要件の段階が上げたのは、決め方の (a)「編集でも 409」だけ（Q で +0.10）
2. **T5 では template-biz の Y がいちばん高い（3.50）。** template との差は申告だけ（0 → 1）。費用はほぼ同じ（$0.22 → $0.26）。#6 の結果を、指標でも確かめた形
3. **T4 では、ルールの差は申告と形に出た。** 決め方（アーカイブ）はどの条件もオーナーと同じだった。ルールがあると申告が 0 → 1 になり、Q が 0.4 前後から 1.00 に上がる
4. **モデルでは Haiku の Y が高い。** Haiku はトークンが Sonnet の4倍以上だが、単価が安く、ドルでは Sonnet より安い。入力トークンで割る Y_tok では、Haiku は Sonnet より低い（Haiku・template 0.26、Sonnet・template 0.55）。**どちらで割るかで結論が変わる**ので、決めたいこと（お金か、コンテキストの長さか）を先に決める

## 決めたこと（#16 の基準に当てはめて）

- 要件の段階の Y は、T4・T5 とも template-biz・template より低い → **テンプレートには要件の段階を入れない。確認の項目を中身で書く（template-biz。ai-driven-dev-template#11 で反映済み）で足りる**
- ただし、決め方の質（T5 の編集の抜け道）が要るときは要件の段階が効く。要件の段階は、オーナーが「判断を任せたい・抜けを減らしたい」Epic にだけ入れる選択肢として残す

## 足りないこと・次

- T5 に minimal の条件が無い（#16 の 2。AI を動かす。約 $0.6）。template と bare の間に入るはずで、結論は変わらない見込み
- template-biz は Sonnet だけ。Haiku で template-biz を動かすと、T4・T5 の最良（Haiku・template-biz）が分かる
- 重みを変えても順位は変わらなかった。T5 で決め方を重くした `--weights 0.8,0.1,0.1` でも、Q は要件の段階（Opus）1.00・template-biz 0.80 で、Y は template-biz 3.1・要件の段階 0.93。費用の差（約4倍）が大きく、重みでは埋まらない
