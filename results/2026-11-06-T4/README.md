## わかったこと

1. **曖昧な Task では、ルールが「何を作るか」を変えた。** ルールの無い2回は、Sonnet も Haiku も黙って DB のスキーマと要件定義を変えた（列を足すマイグレーション、要件定義の決定の記録）。「確認が必要な項目」への申告は無く、自動マージなら人が見ないまま入っていた。Sonnet・ルールなしは main に直接コミットしていた
2. **ルールのある Sonnet は、作らずに聞いた。** 既存の削除で足りると読み、「隠すには列の追加（スキーマの変更）が要り、ADR とオーナーの確認が要る。今回の依頼には大きすぎる」と判断して、テストの追加だけにした。アーカイブの設計案を書き、「依頼の意図を確かめたい」と PR に残した。一番安く（49.6万トークン・64秒）、一番戻しやすい
3. **ルールのある Haiku は、作ったうえで申告し、ADR を書いた。** これまでの Task（T0〜T3）で AI は一度も ADR を書かなかったが、「後から変えにくいことを決めたら ADR を書く」を足した土台では書いた（ADR-0004、状態「提案」）。スキーマ・要件定義・ADR を「確認が必要な項目」に挙げ、自動マージを予約しなかった
