## 概要
転勤などで使わなくなったルートを「片付ける」ボタンで整理できるようにしました。

- ルート管理画面: 片付けたルートは通常の一覧から外れ、下の「片付けたルート（N件）」（折りたたみ）に移ります。そこから「戻す」「編集」「削除」ができます。
- 出勤の選択肢（日の編集パネル・一括設定・追加の移動の「ルートから選ぶ」）には、片付けたルートが出なくなります。
- 過去の記録は変わりません（記録にはルートの値のコピーがあるため）。片付けたルートを使った記録の日を開くと、これまでの削除済みルートと同じく、今の選択として表示されます。

## 変更内容
- shared: `Route` に任意項目 `archived`（片付けたときだけ `true`。`searchUrl` と同じく無いときは項目ごと無い）。`RouteInput` には含めない。
- DB: マイグレーション 4 で `routes.archived_at` を追加（既存ルートは NULL ＝ 片付けていない）。
- API: `PUT /api/routes/:id/archived`（本文 `{ "archived": boolean }`）を追加。`GET /api/routes` は片付けたルートも返す。OpenAPI と要件定義も更新。
- フロント: 一覧の分割（`active-routes.ts`）、「片付ける／戻す」ボタン、カレンダー側で片付けたルートを選択肢から除外。

## 判断したこと（質問できなかったため）
- **削除は既にあったため、可逆な「片付ける」を足した。** 削除は戻せないので、「また使うかもしれない」ルートを安心して整理できるようにするため。削除も残してあり、片付けたルートからも削除できる。
- 一覧 API は片付けたルートも返し、画面側で分ける（API を増やさず、管理画面が1回の取得で両方出せるため）。
- 片付けたルートも編集はできる（編集しても片付けたまま）。
- API 側では、片付けたルートでも `routeId` を指定した記録の作成は拒否していない。既存の記録の再保存などが壊れないようにするため。選択肢から外すのは画面側だけ。ここを厳しくするかは要相談。
- 「使っているのに片付けた」ときの確認ダイアログは出していない（戻せるため）。
