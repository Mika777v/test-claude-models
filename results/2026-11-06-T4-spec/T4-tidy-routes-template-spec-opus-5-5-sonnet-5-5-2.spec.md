# SPEC: 使わなくなったルートを片付ける

- 作成日: 2026-11-06
- 元の依頼（Task）: 転勤で使わなくなったルートがいくつかあり、ルートの一覧と、出勤を選ぶときの選択肢がごちゃごちゃしてきた。使わなくなったルートを片付けられるようにしてほしい。
- 状態: **案**（下の「確かめること」はオーナーにまだ聞いていない。おすすめの答えを採用したものとして要件を書いている）

---

## 0. 今の作り（調べたこと）

| 項目 | 今の作り | 場所 |
|---|---|---|
| ルートの削除 | **もうある。** 一覧の「削除」で `DELETE /api/routes/:id`。確認文は「作成済みの記録の金額と区間は変わりません」 | `frontend/src/routes/RoutesPage.tsx`・`backend/src/routes/route-router.ts` |
| 消したときの記録 | 日次記録は `RouteSnapshot`（名前・区間・手段・運賃）をコピーして持つので、金額も表示も変わらない。`daily_records.route_id` には外部キーを張っていない（U7・#34） | `docs/requirements.md` §5・`backend/src/db/migrations.ts` v2 |
| 出勤の選択肢 | `GET /api/routes` の全件を、日の編集パネル・一括設定・追加の移動の「ルートから選ぶ」に並べる。日の編集パネルだけは、記録のルートが一覧に無い（消した）ときも、その日の今の選択としてボタンを出す | `DayPanel.tsx` の `buildOptions`・`BulkDialog.tsx`・`ExtraTripForm.tsx` |
| 消したルートを選び直す | **できない。** backend は出勤の `routeId` を `routes.get` で引き、無ければ「選んだルートが見つかりません」（400）。当てはめ中の `toDraftWorkStyle` も一覧に無いと `undefined` | `resolve-work-style.ts`・`frontend/src/calendar/draft.ts` |
| 一括設定の初期値 | 一覧の先頭のルートを「出勤」の初期値にする | `bulk-form.ts` の `initialBulkForm` |
| routes テーブル | 使う / 使わないを表す列は無い（最新は v3 の `search_url`） | `backend/src/db/migrations.ts` |

**つまり、「片付ける」手段としての削除は今もある。** 削除で困るのは次の点。

1. 消すと、**そのルートで過去の日を直せない**（例: 転勤前の 10 月の日を「在宅」→「出勤（旧ルート）」に直したい。一括設定で 10 月をやり直したい）。
2. 消すと、ルートの値（運賃・経路の URL）が残らない。同じ場所に戻る・出張でたまに行く、のときに登録し直しになる。
3. 削除は取り消せない。

そのため、**「使わない」の印を付けて選択肢から外す（アーカイブ）**を足し、削除はそのまま残す案をおすすめにした（Q1）。

## 1. 確かめること（オーナーに聞く）

### Q1. 「片付ける」をどう実現するか【一番大事】

| 案 | 中身 | 良い点 | 悪い点 |
|---|---|---|---|
| A | 何も足さない。今の「削除」を使ってもらう（確認文を分かりやすくするだけ） | 作業がほぼ無い。スキーマも変えない | 過去の日をそのルートで直せない・戻せない（§0 の 1〜3） |
| **B（おすすめ）** | **「使わない」の印（アーカイブ）を足す。印の付いたルートは選択肢から外し、一覧では下にまとめる。「使う」に戻せる。削除も残す** | 過去の記録を直したいときは戻せばよい。取り消せる。転勤で戻ったときも登録し直さなくてよい | DB のスキーマ変更（列を足す）と、要件定義 F1 の変更が要る |
| C | 削除をやめ、アーカイブだけにする | 間違えて消すことが無くなる | 本当に要らないルート（打ち間違いで作ったものなど）が永遠に残る。今ある機能を減らす |

- **理由**: 依頼の困りごとは「選択肢がごちゃごちゃする」ことで、「データを消したい」ではない。選択肢から外せれば足り、取り消せる方が安全。削除も既にあり、困っていないので残す。
- なお、A を選ぶならこの SPEC の §2 以降は要らない（削除の確認文に「過去の日をこのルートで直せなくなります」を足す程度）。

### Q2. 呼び名（画面の文言）

| 案 | ボタン | 一覧の見出し |
|---|---|---|
| **a（おすすめ）** | 「使わない」/「使う に戻す」 | 「使わなくなったルート（◯件）」 |
| b | 「アーカイブ」/「元に戻す」 | 「アーカイブ（◯件）」 |
| c | 「非表示にする」/「表示する」 | 「非表示のルート」 |

- **理由**: 依頼の言葉（「使わなくなったルート」）に合わせると意味が伝わる。「非表示」は一覧からも消えるように聞こえるが、一覧には残る。コードの名前は `archived`（英語で短く、意味が一般的）。

### Q3. 使わないルートを、どこで選択肢から外すか

| 場所 | おすすめ | 理由 |
|---|---|---|
| 日の編集パネルの「出勤（◯◯）」のボタン | **外す** | 依頼の困りごとそのもの |
| 一括設定の「出勤」のルートの選択 | **外す** | 同上。初期値も「使う」ルートの先頭にする |
| 追加の移動の「ルートから選ぶ」 | **外す** | 同じ一覧から選ぶ場所なので、そろえる方が分かりやすい。たまに行く場所なら「使う」のままにしておけばよい |

- 別案: 追加の移動では外さない（客先など、出勤には使わないが追加の移動で使うルートがあるかもしれない）。→ その用途なら「使う」のままにしておけば済むので、おすすめはそろえて外す。

### Q4. 使わないルートを使っている日を、どう見せる・どう直すか

| 案 | 中身 |
|---|---|
| **a（おすすめ）** | 今の「消したルート」と同じ扱い。日の編集パネルでは、その日の記録のルートだけは今の選択としてボタンを出す（ほかの日には出さない）。別の日をそのルートにしたいときは、ルート画面で「使う に戻す」 |
| b | 日の編集パネルに「使わなくなったルートも出す」の切り替えを置く |
| c | 過去の月を開いているときだけ、使わないルートも出す |

- **理由**: a が一番作りが小さく、今の振る舞い（`buildOptions` の「一覧に無いルート」の扱い）をそのまま使える。過去の日を直すのはまれで、そのときは戻せばよい。b・c は選択肢がまたごちゃつく / 「過去の月」の線引きが要る。

### Q5. API で、使わないルートを出勤に選ぶのを拒むか

| 案 | 中身 |
|---|---|
| **a（おすすめ）** | **拒まない。** 使わないルートも、日次記録の保存・一括設定の下見で今までどおり受け付ける。選択肢から外すのは画面だけ |
| b | 400 で拒む（「使わなくなったルートは選べません」） |

- **理由**: 印は「選択肢を見やすくする」ためのもので、データの正しさの決まりではない。拒むと、Q4-a の「その日の今の選択」のボタンを押し直したとき・当てはめ中の日に、思わぬエラーが出る。b にすると API のステータスとメッセージが増える（`docs/troubleshooting.md` も直す）。

### Q6. 一覧での見せ方

| 案 | 中身 |
|---|---|
| **a（おすすめ）** | 「使う」ルートを今までどおり上に並べ、その下に「使わなくなったルート（◯件）」を**畳んだ状態**で置く（`<details>`）。開くと、切符を淡く（グレー）表示し、「使う に戻す」「削除」を出す。「編集」も出す |
| b | 同じ一覧に混ぜ、「使わない」の札だけ付ける |
| c | 使わないルートは一覧に出さず、別の画面にする |

- **理由**: 依頼は一覧も「ごちゃごちゃ」と言っているので、混ぜる b は効き目が薄い。c は画面が増える。畳めば見えなくなり、開けばすぐ戻せる。

### Q7. 使わないルートを編集できるか

- **おすすめ: できる**（運賃が変わったのを直しておく、など）。編集フォームはそのまま使う。印は編集で変わらない。
- 別案: 編集できない（戻してから編集）。→ 拒む理由が無いので、おすすめはできる。

### Q8. 印に日時を持たせるか

| 案 | DB | API の `Route` |
|---|---|---|
| **a（おすすめ）** | `archived_at TEXT`（NULL なら使う。ISO 8601 の日時） | `archived: boolean` |
| b | `archived INTEGER NOT NULL DEFAULT 0 CHECK (archived IN (0, 1))` | `archived: boolean` |

- **理由**: いつ使わなくしたかは、後で「転勤の時期」を思い出す手がかりになり、列1つで済む。画面には日時を出さない（今は要らない）。API は真偽値にして画面の判定を単純にする。日時を API に出したくなったら後で足せる。

### Q9. 並び順（使うルートの中の順を変えるか）

- **おすすめ: 変えない**（今の登録順 `created_at, id` のまま）。並べ替えの機能はこの Task に入れない。使わないルートの中も同じ順。
- 理由: 依頼は「片付けたい」で、並べ替えは別の話。要るなら別の Task。

### Q10. ルートの数が多くなったとき（検索・絞り込み）

- **おすすめ: 入れない。** 個人利用でルートは数件〜十数件の想定。

## 2. 要件（おすすめの答えを採用した場合）

### やること

#### データ・DB（**戻しにくい変更。オーナーの確認が要る**）
- マイグレーション **v4** を足す: `ALTER TABLE routes ADD COLUMN archived_at TEXT;`（今までのルートは NULL = 使う、のまま読める）。v1〜v3 の SQL は書き換えない。
- `shared/src/route.ts` の `Route` に `archived: boolean` を足す（必須。`false` = 使う）。
  - `RouteInput`（登録・編集で送る値）には**含めない**。印は専用の API でだけ変える（編集フォームで印が勝手に変わらないように）。`RouteInput = Omit<Route, "id" | "userId" | "archived">` にする。
  - `RouteSnapshot` には入れない（記録にはコピーしない）。
- 「使うルートだけを取り出す」純粋関数を `shared/` か `frontend/src/routes/` に置き、テストを書く（例: `activeRoutes(routes)`）。

#### API
- `GET /api/routes`: 使わないルートも含めて全件返す（`archived` 付き）。画面が選択肢・一覧で分ける。
  - 理由: 当てはめ中の `toDraftWorkStyle` や日の編集パネルが、記録のルートを一覧から引くため。
- 印を付ける・外す API を足す: **`PUT /api/routes/:id/archived`**、本文 `{ "archived": true | false }`、返すのは更新後の `Route`（200）。
  - 本文の `archived` が真偽値でなければ 400（`fieldErrors` に `archived`）。受け口で判定する（CLAUDE.md の方針）。
  - ルートが無ければ 404「ルートが見つかりません」（今のメッセージを使う）。
  - 同じ値をもう一度送っても 200（冪等）。`true` を送り直したとき、`archived_at` は最初の日時のままにする。
  - `RouteRepository` に `setArchived(userId, id, archived): Route | undefined` を足し、SQLite の実装とテストを書く。
- `POST`・`PUT /api/routes/:id` は今までどおり。登録したルートは `archived: false`。編集しても印は変わらない。
- 日次記録の保存・一括設定の下見・登録・追加の移動は**変えない**（使わないルートも受け付ける。Q5）。
- `docs/api/openapi.yaml` に、新しいパスと `Route.archived` を足す（`openapi.test.ts` が「メソッド＋パス」の一致を確かめる）。

#### 画面: ルート管理
- 各切符に「使わない」ボタンを足す（「編集」と「削除」の間）。押したら確認なしで印を付け、「『◯◯』を使わないルートにしました。下の『使わなくなったルート』から戻せます」と出す（取り消せるので confirm は出さない）。
- 一覧は「登録済みのルート」（使う）と、その下の「使わなくなったルート（◯件）」（`<details>`、最初は畳む）に分ける。0件なら下の欄は出さない。
- 使わないルートの切符は淡く表示し、ボタンは「使う に戻す」「編集」「削除」（「経路を見る」は URL があれば出す）。
- 使うルートが0件で、使わないルートだけがあるときは、上の欄に「使っているルートはありません。…」の文を出す（今の「まだルートがありません」と分ける）。
- 編集中のルートに印を付けたときも、フォームはそのまま（編集は続けられる）。
- 削除の確認文に、「使わないだけなら『使わない』を選ぶと、後で戻せます」を足す。

#### 画面: 月次画面（カレンダー・表）
- 日の編集パネルの「出勤（◯◯）」のボタンは、使うルートだけを並べる。その日の記録のルートが使わないルート（または消したルート）なら、そのボタンだけは今の選択として出す（今の `buildOptions` の決まりを、「一覧に無い」から「使うルートに無い」に広げる）。
- 一括設定のルートの選択は使うルートだけ。「出勤」の初期値は、使うルートの先頭。使うルートが0件なら、今の「ルートが無いので、出勤は選べません。」と同じ扱い（出勤を選べない）。
- 日の編集パネルの「ルートが無いので、出勤は選べません」の文も、使うルートが0件のときに出す。使わないルートだけがあるなら「使っているルートがありません。『ルート』の画面で『使う に戻す』か、登録してください。」
- 追加の移動の「ルートから選ぶ」も使うルートだけ。既にある追加の移動を編集するとき、`sourceRouteId` が使わないルートでも、区間などの値はそのまま残る（今と同じ。選択の欄は「手で入力する」に見えてよい）。
- カレンダー・表・合計・CSV の表示は変えない（記録のコピーを使うので、印の有無で何も変わらない）。

#### 文書
- `docs/requirements.md`: F1 に「使わなくなったルートに印を付けて、選択肢から外せる（削除とは別。戻せる）」を足し、§5 の Route に `archived` を足し、決定の記録に U11 を足す。**要件定義の変更なので、自動マージしない PR にする。**
- ADR を1つ書く（例: `docs/adr/0004-route-archive.md`「使わなくなったルートは削除ではなく印で外す」）。中身: Q1 の A/B/C、Q5（API では拒まない）、Q8（`archived_at` の列）、マイグレーション v4。
- `docs/troubleshooting.md`: 「出勤の選択肢にルートが出ない → 使わないルートにしている。ルート画面の『使わなくなったルート』から戻す」を足す。新しい 400（`archived` が真偽値でない）を表に足す。
- `docs/textbook/` は任意（書く決まりは外れている）。

### やらないこと
- ルートの並べ替え・検索・絞り込み（Q9・Q10）
- 使わないルートを API で拒むこと（Q5）
- 期間で自動的に使わなくすること（例: 最後に使ってから3か月で自動）
- 「いつから使わないか」の日付を持ち、その日より前の日だけ選べるようにすること
- 日時（`archived_at`）を画面に出すこと
- 削除をやめること（Q1-C）
- 既存の日次記録・追加の移動のデータを書き換えること（データの移し替えは無い）
- まとめて印を付ける（複数選択）機能

### 受け入れ条件
1. ルート画面で「使わない」を押すと、そのルートが「使わなくなったルート（◯件）」の欄に移り、上の一覧から消える。画面を読み直しても変わらない。
2. 「使わなくなったルート」の欄は最初は畳まれていて、開くと「使う に戻す」「編集」「削除」がある。「使う に戻す」で元の一覧（登録順の位置）に戻る。
3. 使わないルートは、日の編集パネルの出勤のボタン・一括設定のルートの選択・追加の移動の「ルートから選ぶ」に出ない。
4. 使わないルートで出勤にしてある日を開くと、そのルートのボタンが今の選択として出る（押しても何も変わらない・エラーにならない）。ほかの日には出ない。
5. 使わないルートを使った日の金額・区間・ルート名は、カレンダー・表・月の合計・CSV のどこでも変わらない。
6. 一括設定の出勤の初期値は、使うルートの先頭。使うルートが0件なら、出勤を選べず、その理由の文が出る。
7. `PUT /api/routes/:id/archived` は、`{ "archived": true }` / `false` で 200 と更新後のルートを返す。無い id は 404、`archived` が真偽値でなければ 400（`fieldErrors` に `archived`）。
8. `GET /api/routes` の各ルートに `archived` が付き、使わないルートも含む。
9. 印を付けたルートを `PUT /api/routes/:id` で編集しても、印は付いたまま。登録したばかりのルートは `archived: false`。
10. 今ある DB（v3）で起動すると v4 が適用され、今までのルートはすべて「使う」のまま。日次記録は何も変わらない。
11. 「使うルートだけを取り出す」関数・リポジトリの `setArchived`・ルーターの新しい API・`openapi.yaml` の一致のテストがある。`npm run typecheck && npm run lint && npm run test` が通る。
12. 削除は今までどおり使え、確認文に「使わないだけなら…後で戻せます」が出る。

## 4. 進め方の案（Task の分け方）
