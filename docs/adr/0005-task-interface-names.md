# ADR-0005: 過去の PR をやり直す Task では、テストが使う名前と形を Task の本文に足してよい

- 状態: 提案（オーナーの確認待ち）
- 日付: 2026-11-06
- 関係する Issue・PR: このADR の PR・[ADR-0003](0003-tasks-from-routepense-prs.md)

## 背景

ADR-0003 では「土台に無い関数名・ファイル名に頼るテストしか無い PR は選ばない（Issue に名前が書いてあれば使ってよい）」とした。
R2・R3 を選ぶときに routepense の機能の PR を調べると、約25のうち 22 が、テストで土台に無い名前（新しい関数・定数）を使っていた。この決まりのままでは、使える PR が3つほど（#53・#54 は一部・#63）しか残らない。

## 選択肢

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| A | ADR-0003 のまま（名前に頼る PR は使わない） | Task が Issue のまま | Task が増えない |
| B | テストが使う名前と形（関数名・引数・返す値の形・置き場所）だけを、Task の本文の「名前と形」の節に足す | 多くの PR を使える。足すのは名前と形だけで、中身（何を返すか・決め方）は足さない | 名前を決める判断は測れなくなる。足した分だけ Issue より易しくなる |
| C | テストを書き直して、外から見える振る舞い（API・画面）だけで確かめる | 名前に頼らない | 実際の PR のテストそのままではなくなり、手間もかかる |

## 決定（提案）

B。足すのは**テストが使う名前と形だけ**にする。

- 節の名前は「名前と形（この名前で作る）」。Issue の本文には無かったことが分かるように、`config.sh` のコメントにも書く
- 書くのは: ファイルの場所・関数や定数の名前・引数・返す値の形（例: 「列の順の文字列の配列」）
- 書かないもの: 中身の決まり（要件定義にあるもの）・Issue に無く PR で決めたこと（決め方のテストで測るため）
- 名前を決める判断そのものを測りたいときは、A か C の Task を使う

## 理由

- 名前の付け方は、この検証で決めたいこと（ルール・モデルの効果）とほぼ関係が無い。名前が違うだけで正しさのテストが落ちると、正しさの関門が意味を失う
- R2（#84）で試した。要件定義 F7 に中身が書いてあり、足したのは名前と形だけで、dry は期待どおりだった

## 影響

- R2-month-csv はこの作り方で作った。この ADR を取り下げるなら、R2 は使わない
- Task が Issue より易しくなる分、難しさの段（ADR-0004）は1つ下げて考える
