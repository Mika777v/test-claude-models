# ADR-0007: Y の分母は、まず入力トークン（成功1回あたり）にする

- 状態: 決定（2026-11-09 にオーナーが決めた）
- 日付: 2026-11-09
- 関係する Issue・PR: [ADR-0004](0004-evaluation-score.md)・[T4・T5 の測り直し](../../bench/results/2026-11-09-T4-T5-score/README.md)

## 背景

ADR-0004 は、コストをドルと入力トークンの2つで出し、決めたいことに合うほうを分母にするとした。T4・T5 の測り直しで、どちらで割るかでモデルの結論が逆になった（Haiku はトークンが Sonnet の4倍以上だが、単価が安くドルでは安い）。

費用は「トークンの数 × 単価」で決まる。単価はトークンの種類（入力・出力・キャッシュの作成・キャッシュの読み出し）とモデルで違う。例（R2 の bare の1回目、Sonnet）: 30万トークンのうち 27万（89%）はキャッシュの読み出しで、単価は入力の 1/10。出力は 9千（3%）だが、単価が入力の5倍で、費用の約4割を占めた。

## 選択肢

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| A | 入力トークン（入力 + キャッシュの作成 + 読み出し）を分母にする | モデルの単価や値下げに左右されない。読んだ量（コンテキストの使い方）をそのまま見られる | 実際のお金とずれる（キャッシュの読み出しは安く、出力は高い）。単価の違うモデルどうしでは比べにくい |
| B | ドルを分母にする | 実際のお金 | 単価が変わると、過去の結果と比べられなくなる |

## 決定

A を既定にする。`summarize.mjs` の Y_tok を主に読み、Y（ドル）は並べて出す。

- **ルールの比べ（同じモデルで条件を変える）**: 入力トークンで読む。単価が同じなので、トークンの差がそのまま読んだ量の差になる
- **モデルの比べ**: 入力トークンで読んだうえで、ドルの Y も必ず並べて書く（どちらで割るかで結論が変わることがある）

## 理由

- オーナーの判断（2026-11-09）
- この検証で決めたいのは「ルールの文書をどこまで書くか」が中心で、それは AI が読む量（入力トークン）に効く
- 単価はモデルの代替わりで変わる（このリポジトリの測定の間にも、モデルが入れ替わっている）。トークンなら、後から比べ直せる

## 影響

- 結果の README では、Y_tok を先に書く
- 出力トークンは分母に入れない。出力の多さ（長い PR の本文など）を見たいときは、`tokens_out` を別に並べる
