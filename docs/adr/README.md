# ADR（設計判断の記録）

後から変えにくい判断（データの置き場所・方式の選択・外部サービスの採用など）を、選択肢と理由と一緒に残す。
AI は「なぜこうなっているか」をコードから読み取れないため、ここが理由の正本になる。

- ADR を追加・変更する PR は、自動マージせずに人が読んでからマージする（`AGENTS.md` §3-4）
- 新しく書くときは [`0000-template.md`](0000-template.md) をコピーする。ファイル名は `NNNN-内容.md`（連番）
- **一度決めた ADR は書き換えない。** 判断を変えるときは新しい番号の ADR を足し、古いほうの「状態」を「置き換え（ADR-NNNN）」にする

| 番号 | タイトル | 状態 |
|---|---|---|
| [0000](0000-template.md) | （テンプレート） | — |
| [0001](0001-move-agent-bench-to-dedicated-repo.md) | agent-bench をテンプレートから分け、このリポジトリの bench/ に履歴ごと置く | 決定 |
| [0002](0002-bench-base-and-conditions.md) | 測定の土台を routepense の固定コミットにし、条件は「ルールの文書を消す量」で分ける | 決定 |
| [0003](0003-tasks-from-routepense-prs.md) | Task を routepense の過去の PR から作り、実際にマージした結果を正解にする | 決定 |
| [0004](0004-evaluation-score.md) | 評価の指標を「正しさの関門 ＋ 品質の点 Q ÷ 成功1回あたりのコスト」にし、Task は難しさの段ごとにまとめる | 決定 |
| [0005](0005-task-interface-names.md) | 過去の PR をやり直す Task では、テストが使う名前と形を Task の本文に足してよい | 提案 |
| [0006](0006-declare-point-when-no-section.md) | 確認が要らない Task で「確認が必要な項目」を書かなかった回は、申告を 0.5 点にする | 決定 |
| [0007](0007-cost-by-input-tokens.md) | Y の分母は、まず入力トークン（成功1回あたり）にする | 決定 |
