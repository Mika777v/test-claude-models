## 概要

その日の記録に、自由なメモ（例: 「健康診断で直帰」「客先の住所が変わった」）を付けられるようにしました。

## 変更内容

### API・データ
- `PUT /api/daily-records/{date}/note` を追加しました。本文は `{ "note": "..." }` です。
  - 前後の空白を除いて保存します。空、または空白だけを送るとメモを消します。
  - その日の記録が無いときは 404 を返します。空を送った場合も 404 です。
  - `note` が 201 文字以上のとき、文字列でないとき（`null` やキーが無い場合を含む）は 400 を返します。`fieldErrors[].field` は `"note"` です。
  - 返すのは、メモを付けた後のその日の `DailyRecord` です。
- `DailyRecord` に `note?: string` を足しました。メモが無い日は、プロパティごと付けません。
- `daily_records` に `note TEXT` 列を足しました（マイグレーション 4）。今までの記録は `NULL`（メモなし）のまま読めます。
- 勤務区分の保存（`PUT /api/daily-records/{date}`）と一括設定の登録（`POST /api/daily-records/bulk`）は、UPSERT の更新対象に `note` 列を入れていません。そのため、どちらでもメモは残ります（テストで確認済み）。
- 月の取得（`GET /api/daily-records?month=`）でもメモを返します。
- `docs/api/openapi.yaml` と `docs/requirements.md`（F2・F5・F7・データの項目・U11）を更新しました。

### 画面
- 日の編集パネルに「メモ」の欄を足しました。2 行のテキストエリアで、「メモを保存」ボタンを押すと保存します。

- 未入力の日は記録が無いので、メモの欄の代わりに「メモと追加の移動は、先に勤務区分を選んでから付けられます。」と出します。
- 一括設定の当てはめ中は、メモを読むだけにしました。「メモ: …（登録しても残ります）」と表示します。
- 表表示の最後に「メモ」の列を足しました。

### CSV

## 自分で決めたこと
- **メモの保存方法**: 勤務区分はボタンを押した時点で保存します（U4）。一方メモは自由に入力する欄なので、書きかけの状態で保存されないよう「メモを保存」ボタンで保存するようにしました。
- **CSV の行の作り方は変えていません**: メモがあっても、移動の無い日（在宅・休日で追加の移動が無い日）は今までどおり行を作りません。そのため、その日のメモは CSV に出ません。「1 行 = 1 つの移動」（F7・U10）の決まりと、「金額の列の和 = 月の合計」の性質を保つためです。
- **文字数の数え方**: 既存の `MAX_TEXT` の検証と同じく、JS の `String.length`（UTF-16 のコード単位）で数えます。そのため、絵文字などのサロゲートペアは 1 文字を 2 として数えます。上限の 200 は `shared` の `MAX_NOTE` に置き、backend と画面の両方で使います。
- **改行**: メモの中の改行は受け付けます（テキストエリアのため）。CSV では RFC 4180 に従って `"` で囲みます。
- **カレンダーのマス**: メモの印は付けていません。この Task の範囲（日の編集パネルと表）に絞りました。必要なら、別の Task で足します。
- **`note: null` は 400**: Task の「文字列でないときは 400」に合わせました。消すときは空文字を送ります。
